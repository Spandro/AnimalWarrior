# Taverne – Implementierungsplan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Eine Taverne als dritter Punkt der Modusauswahl. Dort gibt es drei Glücksspiele um Gold und seltene Beute, eine Truhe mit 24 Gegenständen und den Stall. Im Stall wird für 20.000 Gold das Duo Giraffe und Erdmännchen freigeschaltet, das danach im Wellen-Modus spielbar ist.

**Architecture:**
- Die Spielregeln (Würfeln, Rad, Kartenschritte, Beutewurf) sind reine Funktionen in `src/core/tavern.js` mit übergebenem Zufall. Ihre Zahlen stehen in `src/data/tavern.js` und `src/data/items.js`.
- Das Verrechnen mit dem Spielstand liegt wie bei den Dauerboni in `src/save/tavern.js`. Die Funktionen verändern den übergebenen Stand und werden über `app.update` aufgerufen.
- Das Duo ist ein viertes Tier `giraffe` mit fest zugeordneter Klasse `hochstapler`. Welche Tier-Klasse-Paare erlaubt sind, beantwortet `src/core/roster.js`.
- Die Oberfläche besteht aus neuen Menübildschirmen nach dem Muster der vorhandenen.

**Tech Stack:** JavaScript ES-Module ohne Build, Three.js 0.170.0 (`vendor/`), CSS, Web Audio, Tests in `tests.html`.

**Spec:** `docs/superpowers/specs/2026-11-13-taverne-design.md` (freigegeben am 2026-11-13; baut auf den beiden älteren Specs unter `docs/superpowers/specs/` auf)

## Global Constraints

- Kein Node.js, kein Build, keine CDN-Abhängigkeit zur Laufzeit; alle Pfade relativ (kein führendes `/`).
- `src/core`, `src/modes`, `src/data`, `src/save` importieren weder Three.js noch greifen sie auf `window`, `document`, `localStorage`, `Date.now()` zu. Zufall dort nur über `createRng(seed)`. Startwerte für Taverne-Runden erzeugt die Oberfläche (`crypto.getRandomValues`).
- `src/render` und `src/ui` ändern den Weltzustand eines Durchgangs nie. Den Spielstand ändern sie nur über `app.update(mutator)` mit Funktionen aus `src/save/`.
- Alle Balancing- und Gestaltungszahlen stehen in `src/data/`.
- Oberfläche auf Deutsch; Text nur über `textContent`. Alle Pixelangaben sind CSS-Pixel.
- Neue Spielstand-Version **3** mit Umwandlung 2 → 3. Alte Stände und Exporte (Version 1 und 2) laden ohne Verlust.
- Kennungen von Gegenständen werden nie gelöscht oder umbenannt.
- **Kein Spiel zahlt im Schnitt mehr als 95 % in Gold aus.** Mit dem Gegenwert verkaufter Doppelter bleibt jede Taverne-Runde unter 97 %.
- Rundenergebnisse werden **vor** der Animation verrechnet und gespeichert.
- Fehlt ein Bild oder Ausschnitt, gibt es Ersatz (Spec Abschnitt 9). Kein Bildschirm darf an einem fehlenden Bild scheitern.
- Alle Taverne-Bildschirme bei 360 × 640 und 390 × 844 ohne seitliches Scrollen, Knöpfe mindestens 44 px hoch. Bei „Bewegung reduzieren“ keine Animationen, das Ergebnis erscheint sofort.
- Hase, Ente und Waschbär bleiben unverändert. Der Wellen-Modus ändert sich nur dadurch, dass das Duo als Held dazukommt.
- **Git:**

## Review Focus

1. **Doppeltippen auf „Würfeln“ oder „Drehen“ während der Animation, oder Einsatz größer als das Gold**
   - Erwartet: genau eine Runde, kein doppeltes Abbuchen, kein negatives Gold.
   - Tests in Aufgabe 3 (`applyRound` lehnt ab). Der Knopf ist während der Animation gesperrt (Aufgabe 7).
2. **Zurück, Esc, Neuladen oder Tab-Wechsel mitten in Höher oder tiefer**
   - Erwartet: Der Einsatz ist weg, der Topf auch, nichts wird doppelt gutgeschrieben. „Zurück“ fragt nach, solange ein Topf da ist.
   - Tests in Aufgabe 2 (Tipp nach Rundenende wird abgelehnt) und Aufgabe 3 (`settleHiLoRound` zweimal schreibt nur einmal gut).
3. **Import eines Spielstands mit Duo-Held, aber ohne Freischaltung oder mit falschem Paar** (z. B. `giraffe` als Krieger)
   - Erwartet: Ablehnung mit Meldung, der vorhandene Stand bleibt.
   - Tests in Aufgabe 3.
4. **Gold aus einem Erfolg oder aus einer Runde überschreitet 1.000**
   - Erwartet: „Sparschwein“ wird sofort freigeschaltet und eingeblendet, nicht erst nach dem nächsten Durchgang.
   - Test in Aufgabe 3 (`unlockStored` nach `applyRound`). Anbindung in Aufgabe 7.
5. **Offene Karte Ass oder 2 bei Höher oder tiefer**
   - Erwartet: Die unmögliche Wahl ist gesperrt. Eine fast sichere Wahl zeigt ×1,0 und bringt nie mehr als den Einsatz.
   - Tests in Aufgabe 2.

**Files:**
- Create: `src/data/tavern.js`, `tests/tavern.test.js`

**Interfaces:**
- Consumes: `rollItem(rng)` (Aufgabe 1)
- Produces:
  - In `src/data/tavern.js`:
    - `TAVERN = { stakes: [10, 50, 100, 500], lootMinStake: 100, duoPrice: 20000 }`
    - `DICE = { winMul: 2, tieMul: 0.5 }`
    - `WHEEL = { fields: WheelField[] }` mit genau 20 Feldern, `WheelField = { kind: 'niete'|'mult'|'loot', mul: number }`. Verteilung: 10 Nieten, 4 mal ×1, 3 mal ×2, 1 mal ×3, 1 mal ×5, 1 Beutefeld. Die Nieten sind über das Rad verteilt, nicht in einem Block.
    - `HILO = { rtp: 0.93, maxHits: 5, potCapMul: 50, jokerChance: 0.02, ranks: [2..14], rankLabels: { 11: 'B', 12: 'D', 13: 'K', 14: 'A' } }`
    - `HOSTS = { affe: { name: 'Kasimir', animal: 'Affe', lines: { dice: string[], hilo: string[] } }, elster: { name: 'Madame Funkel', animal: 'Elster', lines: { wheel: string[] } } }` mit je Tisch 6–8 Sprüchen im Ton der Erfolge.
    - `TABLE_HOST = { dice: 'affe', wheel: 'elster', hilo: 'affe' }`: Kasimir betreut Würfelbecher und Kartentisch.
  - In `src/core/tavern.js`:
    - `playDice(rng, stake): { player: [number, number], host: [number, number], outcome: 'win'|'tie'|'lose', payout: number, loot: string|null }`
      - Gewinn zahlt `stake × 2`, Gleichstand `Math.floor(stake × 0.5)`, Niederlage 0.
      - `loot` gibt es nur bei einem Sechserpasch des Spielers und `stake >= 100`.
    - `spinWheel(rng, stake): { index: number, payout: number, loot: string|null }`
      - `payout = stake × mul`.
      - Beutefeld: ab 100 gibt es `loot` und `payout` 0, darunter `payout = stake`.
    - `hiLoFactor(card: number, dir: 'up'|'down'): number`
      - `p` = Anteil der 13 Werte, die echt höher bzw. tiefer sind.
      - Faktor = `Math.floor(0.93 / p × 10) / 10`, bei `p = 0` ist er 0.
    - `HiLoState = { stake, pot, card, hits, done: boolean, result: null|'miss'|'joker'|'cashout'|'max' }`
    - `hiLoStart(rng, stake): HiLoState`. Die Startkarte ist nie ein Joker, `pot = stake`.
    - `hiLoGuess(state, dir, rng): { state: HiLoState, drawn: number|'joker', loot: string|null }`
      - Erst der Joker-Wurf (2 %), dann der Kartenwert. Gleicher Wert zählt als Fehltipp.
      - Treffer: `pot = Math.floor(pot × factor)`.
      - Ist `hits === 5` oder `pot >= stake × 50`, gilt `done` mit `result: 'max'`, und `pot` wird auf `stake × 50` gedeckelt.
      - Joker: `done` mit `result: 'joker'`, `pot` bleibt, `loot` ab 100.
      - Liefert ein neues Objekt.
      - Wirft einen Fehler bei `done`-Zustand oder bei Faktor 0.
    - `hiLoCashOut(state): HiLoState`. Wirft einen Fehler, wenn `hits === 0` oder `done`.
    - Genaue Quoten für Tests und Anzeige, ohne Zufall:
      - `diceReturn(): number`
      - `wheelReturn(stake): number`
      - `hiLoStepReturn(card, dir): number` mit dem Joker: `0.98 × p × Faktor + 0.02 × 1`
